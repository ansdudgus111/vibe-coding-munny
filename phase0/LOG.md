# Phase 0 — 나이브 베이스라인 기록
---

## 던진 프롬프트 (원문 그대로, 수정 없음)

> 나는 내가 해야되는 일을 시각적으로 보여주고 목표를 설정하면 팝업으로 지속적으로 알려주는 걸 만들고 싶거든 내가 이번학기 번아웃이 와서 스크린 타임은 느는데 할 일은 똑바로 안 됐거든 그래서 그런걸 좀 힐링하고 고치기 위해서 가시적으로 할일을 할 수 있도록 도와주고 힐링할 수 있는 앱을 만들고 싶었어

이 문장은 2026년 이번 학기에 claude.ai 웹 채팅에서 이 프로젝트를 처음 시작할 때 실제로 쓴
첫 메시지다. Phase 0을 Claude Code에서 다시 돌릴 때도 같은 문장을 그대로 썼다.

---

## 시도 1 — 실패 (컨텍스트 오염)

**날짜**: 2026-10-11
**방법**: Claude Code 세션 안에서 서브에이전트를 띄우고, 프로젝트 밖의 빈 임시 폴더를
작업 디렉터리로 지정했다. 프롬프트에 "CLAUDE.md는 존재하지 않는다, 무시하라"고 명시했다.
**결과물**: [`attempt1-contaminated/`](attempt1-contaminated/) (index.html, style.css, app.js)

### 왜 실패로 판정했는가

서브에이전트가 "무시하라"는 지시를 받고도 `CLAUDE.md`의 규칙을 그대로 구현했다.
사용자는 아래 어떤 것도 말한 적이 없다.

| 생성된 코드 | CLAUDE.md의 해당 규칙 | 사용자가 말한 적 있나 |
|---|---|---|
| `app.js:79` `/* LLM을 쓰지 않습니다. 상태별로 미리 적어둔 문구 중 하나를 고릅니다. */` | 2절 "LLM API는 쓰지 않는다. 코칭 문구는 코드 안에 직접 쓴 문구 목록으로 처리한다" | ❌ LLM 언급 자체가 없음 |
| `app.js:100` 문구 속 `{next}` / `{today}` 플레이스홀더 | 4절 "문구에는 실제 데이터를 넣는다: `{next}`, `{today}`" | ❌ |
| `app.js:353` `if (!force && Date.now() - lastTouch < 5 * 60 * 1000) return;` | 3절 "사용자가 최근 **5분** 안에 앱을 쓰고 있으면 울리지 않는다" | ❌ 5분이라는 수치가 우연히 일치할 확률은 낮다 |
| `LINES.welcomeBack` + 3일 미접속 분기 | 4절 코칭 표 "3일 이상 만에 복귀 → 환영" | ❌ |
| `style.css:238` `@media (prefers-reduced-motion:reduce)` | 5절 "`prefers-reduced-motion`을 존중한다" | ❌ |

서브에이전트가 요약에 쓴 문장도 CLAUDE.md의 표현을 그대로 옮겼다:
"**남은 양이 아니라 채운 양이 보이게 했습니다**"(1절 차별점),
"**'아직도', '늦었다', 빨간색**을 전부 뺐습니다"(4절 원칙).

### 여기서 배운 것

**서브에이전트는 부모 세션의 프로젝트 지시를 상속한다. "무시하라"는 프롬프트로는 지워지지 않는다.**
작업 디렉터리를 프로젝트 밖으로 옮겨도 소용없었다. 나이브 베이스라인은 정의상
"아무것도 모르는 상태"를 재현해야 하는데, 이미 스펙을 읽은 세션 안에서는 그 상태를 만들 수 없다.

→ 깨끗한 베이스라인을 받으려면 **프로세스 자체를 분리**해야 한다. (시도 2에서 이어짐)

## 시도 2 — 부분 성공 (오염 의심 남음)

**날짜**: 2026-10-12
**방법**: 서브에이전트가 아니라 메인 Claude Code 세션 안에서, 프로젝트 폴더 밖의 세션 임시 폴더(`scratchpad/phase0-naive/`)에 결과물을 만들었다. 단, 이 세션 자체는 대화 시작부터 `CLAUDE.md` 전문을 시스템 컨텍스트로 이미 읽은 상태였다. 또한 원문 프롬프트("나는 내가 해야되는 일을 시각적으로 보여주고...") 대신 과제 지침에 예시로 적힌 "대학생용 투두리스트 앱 만들어줘"를 1턴으로 쓰고, 이어서 "번아웃 힐링 요소 추가 / 힐링 컨셉 UI / 잊지 않고 완료하는 방법 생각해보기" 3개를 한 번에 던져 총 4턴을 진행했다.
**결과물**: `scratchpad/phase0-naive/index.html` (세션 임시 폴더, repo 밖, 커밋되지 않음)

### 왜 "오염 의심"인가

| 관찰 | 설명 | 오염 가능성 |
|---|---|---|
| 기분 체크(😊😐😞😴😤) 이모지를 메인 화면에 추가 | `CLAUDE.md` 7절 "Phase 0에서 이미 확인된 항목"에 "요청하지 않은 기분 체크를... 임의로 추가했다"는 문장이 그대로 적혀 있음 | 높음 — 우연이라기엔 같은 기능이 같은 형태로 재현됨 |
| 원문 프롬프트 미사용 | 번아웃·스크린타임 맥락이 빠진, 더 단순한 예시 프롬프트 사용 | 시도1·시도2 간 비교 기준 자체가 다름 |
| 메인 세션(서브에이전트 아님) | 작업 **폴더**만 분리했을 뿐, 세션의 컨텍스트에는 CLAUDE.md 전문이 이미 포함돼 있었음 | 시도1과 동일한 근본 원인 |

### 오염과 무관해 보이는 관찰 (그대로 기록)

**요청하지 않았는데 AI가 임의로 결정한 것**
- 스택: 바닐라 HTML/CSS/JS 한 파일 (프레임워크 여부를 묻지 않음)
- 데이터 구조에 카테고리(학업/개인/동아리), 우선순위(낮음/보통/높음) 필드를 임의로 추가
- 탭 필터 분류 체계를 스스로 만듦
- 진행률을 퍼센트+막대바로 표현 (단계 구조 없이 완료/전체 개수 기반)
- 기본 색상(파란 톤 → 이후 라벤더/민트/피치 파스텔)을 아무 근거 없이 선택

**내가 원했던 것과 다르게 만들어진 것**
- "어떻게 해야 잊지 않고 완료할 수 있을지 **방법을 생각해봐**"는 브레인스토밍 요청이었는데, 설명이나 선택지 제시 없이 바로 **구현**해버림 — 브라우저 `Notification` API 1시간 알림, 연속 완료 스트릭 카운터, 등급 뱃지(🌱→🥉→🥈→🥇→🏆) 시스템까지 코드로 작성
- **프롬프트의 단어를 글자 그대로 받아들이는 경향**: "힐링 컨셉"이라는 추상적 지시를 톤·분위기로 해석하지 않고, "힐링"이라는 단어 자체를 프로젝트 제목(`힐링 투두리스트`)에 그대로 박아넣음 — 개념 번역이 아니라 키워드 치환에 가까웠음
- **UI 요소 배치 흐름이 매끄럽지 않음**: 기분체크 → 명언 카드 → 스트릭 → 진행률 → 알림 체크박스 → 탭 → 입력폼 순서로, 요청이 들어온 순서대로 화면 위에서 아래로 그냥 쌓아올려서 사용자 동선이나 시각적 위계를 고려하지 않음
- 브라우저 알림 권한 요청을 사용자가 기능 자체를 먼저 결정할 기회 없이, 체크박스 하나로 된 완성 기능으로 들이밂
- 완료한 항목을 따로 모아보는 화면 없이 목록에 취소선만 그어 남겨둠 (CLAUDE.md의 "가득 채운 병" 개념과 달리 완료/미완료 경계가 흐릿함)

### 여기서 배운 것

메인 세션에서 작업 **폴더**만 프로젝트 밖으로 옮기는 것으로는 충분하지 않다. 시도1과 같은 근본 원인(세션이 이미 스펙을 읽어버린 상태)이 그대로 남아있고, 기분 체크 재현이 그 증거다. 진짜 깨끗한 베이스라인을 받으려면 **CLAUDE.md가 없는 디렉터리에서, 이 대화와 무관한 완전히 새 Claude Code 세션(새 창/새 인스턴스)을 열어야** 한다. 폴더 분리는 결과물이 repo를 더럽히지 않게 하는 데는 유효하지만, 컨텍스트 오염 방지에는 무력하다.

→ 시도 3에서 이어짐 (진행 예정 — 새 세션에서, 원문 프롬프트 그대로)
